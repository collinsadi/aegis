# Aegis × 0G — Integration Deep Dive

**Network:** 0G Testnet (chain ID 16602)  
**Storage Indexer:** `https://indexer-storage-testnet-turbo.0g.ai`  
**Storage RPC:** `https://evmrpc-testnet.0g.ai`  
**Compute Endpoint:** `https://api.0g.ai/v1`  
**Compute Model:** `qwen3.6-plus`  

---

## Why 0G

Aegis needed two things that Ethereum alone cannot provide cheaply: persistent off-chain storage for 1952-byte ML-DSA public keys, and verifiable AI inference for autonomous threat scoring. 0G provides both through a single SDK with a flag to turn it on.

Without 0G: keys live in Postgres (restarts lose nothing, but it's a centralised dependency). Threat scores use hardcoded factor weights — deterministic but not intelligent.

With 0G: keys are content-addressed and replicated across decentralised storage nodes. Threat scores come from an LLM running inside a TEE, making the inference auditable without revealing the model's internals.

## 0G Storage — ML-DSA Key Persistence

The CCIP-Read gateway (`server/`) is the off-chain component that serves 1952-byte ML-DSA public keys when the on-chain resolver redirects to it. Normally it uses Prisma + Postgres. With `ENABLE_ZERO_G=true` it uses `ZeroGKeyStore` instead.

### How it works

```
POST /register  ──→  ZeroGKeyStore.set()
                       │
                       │  MemData(1952 bytes)
                       ▼
                     Indexer.upload(file, rpc, signer, { expectedReplica: 1 })
                       │
                       │  returns { rootHash, txHash, txSeq }
                       ▼
                     rootIndex[node] = rootHash  (in-memory pointer)

GET /ccip/:sender/:data  ──→  ZeroGKeyStore.get(node)
                                │
                                ├─ cache hit?  → return immediately
                                │
                                └─ cache miss  → rootIndex[node] → rootHash
                                                  │
                                                  ▼
                                               Indexer.downloadToBlob(rootHash)
                                                  │
                                                  ▼
                                               Buffer.from(blob.arrayBuffer())
```

The Merkle root is the content address of the key. Fetching the same root from any 0G storage node returns the same bytes — the protocol guarantees it.

| File | Role |
|------|------|
| `server/src/services/zerogKeyStore.ts` | Upload / download logic |
| `server/src/services/keyStoreFactory.ts` | Returns `ZeroGKeyStore` or Prisma `KeyStore` based on flag |

## 0G Compute — AI Threat Scoring

`ZeroGQuantumOracle` extends the base `QuantumOracle`. When `ENABLE_ZERO_G=true`, calling `computeThreatScore()` sends the currently active threat factor names to the 0G Compute API (OpenAI-compatible endpoint) and asks `qwen3.6-plus` to reason a score 0–100.

### Prompt design

```
You are a quantum cryptography threat analyst evaluating risks to
ECDSA-based Ethereum wallets. The following threat signals are active:

1. secp256k1_cve_published
2. logical_qubits_above_1000

Score the aggregate threat level from 0 to 100 where:
- 0-30:  Low risk, no action needed
- 31-60: Moderate risk, monitor closely
- 61-89: High risk, begin migration planning
- 90-100: Critical, immediate deprecation required

Respond with ONLY valid JSON: {"score": <int>, "reasoning": "<one sentence>"}
```

The LLM response is parsed, the score is clamped to `[0, 100]`, and it is returned as the threat level. Any failure (network error, malformed JSON, API timeout) falls back to the hardcoded weighted sum from the parent class — the oracle never goes silent.

The inference runs inside a TEE on 0G Compute nodes, which means the output is verifiable without requiring the model weights to be public.

|------|------|

| `config/ens.config.ts` | `INTEGRATIONS.ZERO_G.COMPUTE_ENDPOINT` / `COMPUTE_MODEL` |

## Configuration

All 0G behaviour is gated by `ENABLE_ZERO_G=true` in `.env`. When the flag is off (or missing), every code path falls back to the original Aegis behaviour with zero changes.

```bash
# server/.env
ENABLE_ZERO_G=true
ZERO_G_PRIVATE_KEY=<funded 0G testnet wallet>
ZERO_G_STORAGE_RPC=https://evmrpc-testnet.0g.ai
ZERO_G_STORAGE_INDEXER=https://indexer-storage-testnet-turbo.0g.ai
ZERO_G_COMPUTE_ENDPOINT=https://api.0g.ai/v1
ZERO_G_COMPUTE_MODEL=qwen3.6-plus
```

## Running the Tests

```bash
cd server
npm run test:0g
# Requires ENABLE_ZERO_G=true, ZERO_G_PRIVATE_KEY set, and server running on :8080
# 17 assertions across 5 test sections — all passing
```

Test sections:
1. **ZeroGKeyStore direct** — upload 1952 random bytes → clear cache → download → byte-exact match
2. **Factory routing** — `activeKeyStore` resolves to `ZeroGKeyStore`
3. **POST /register** — real aria-f0pi key, on-chain verification, 0G upload
4. **GET /ccip** — encoded node hash, server returns ABI-encoded 1952-byte key
5. **GET /health** — server up, key count reported
